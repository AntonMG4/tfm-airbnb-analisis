Introducción

Este documento recoge la fase de ETL (Extracción, Transformación y Carga) del dataset de Airbnb (2008-2021) proporcionado para el TFM. El objetivo de esta fase es dejar un conjunto de datos limpio, documentado y listo para las fases posteriores de clustering y modelado predictivo de precio.

A lo largo del documento no solo se aplican las transformaciones, sino que se documenta el razonamiento y la evidencia que llevó a cada decisión — muchas hipótesis iniciales (basadas en la documentación genérica del dataset) se contrastaron con los datos reales y se revisaron cuando la evidencia no las respaldaba. Esa validación empírica es en sí misma parte del valor de esta fase.

2. Conversión de moneda

Dado que solo hay 10 ciudades (sección 1.4), se construye una tabla de mapeo manual ciudad → país → moneda → tipo de cambio, en vez de inferir el país mediante coordenadas (innecesario para solo 10 valores conocidos).

Fuente de los tipos de cambio: European Central Bank, Euro foreign exchange reference rates, 31 de agosto de 2026. https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml

2.1 Detección de outliers de precio

Al observar los precios más altos ya convertidos a EUR, varios de ellos combinan un precio desproporcionado con ausencia de reseñas (review_scores_rating NA). Antes de definir un criterio de outlier, se comprueba con un umbral exploratorio fijo si ese patrón (precio extremo + sin reviews) es general en las 10 ciudades o un caso aislado:

    pct_sin_reviews = mean(is.na(review_scores_rating)) * 100

El contraste es claro: 32,6% de los listings sin reviews en el conjunto general (price_eur <= 2000), frente a un 33%-87,5% dentro del grupo de precios extremos (price_eur > 2000), y presente en las 10 ciudades, no solo en una. Este patrón es consistente con una práctica conocida de Airbnb: fijar un precio disparatado para bloquear el calendario de disponibilidad en lugar de pausar el anuncio, en vez de un error de captura de datos. El umbral fijo de 2.000€ es solo exploratorio (penaliza de forma desigual a ciudades con escalas de precio muy distintas, como Istanbul frente a Sydney); para la variable definitiva se usa un umbral relativo por ciudad:

Code 
listings <- listings %>%
  group_by(city) %>%
  mutate(
    q1 = quantile(price_eur, 0.25),
    q3 = quantile(price_eur, 0.75),
    iqr = q3 - q1,
    umbral_outlier = q3 + 3 * iqr
  ) %>%
  ungroup() %>%
  mutate(precio_sospechoso = price_eur > umbral_outlier & is.na(review_scores_rating))

3.1 review_scores_*

Las 7 variables de puntuación (rating + 6 subpuntuaciones) están fuertemente correlacionadas en su missingness: la inmensa mayoría de los nulos corresponde a listings sin reseñas todavía, no a datos perdidos por error.

Code 
listings <- listings %>%
  mutate(has_reviews = !is.na(review_scores_rating))

Antes de decidir cómo imputar, se identifican los casos con rating presente pero alguna subpuntuación ausente (un problema distinto al de los listings sin reviews):

Code 
listings %>%
  filter(!is.na(review_scores_rating) &
         (is.na(review_scores_accuracy) | is.na(review_scores_cleanliness) |
          is.na(review_scores_checkin) | is.na(review_scores_communication) |
          is.na(review_scores_location) | is.na(review_scores_value))) %>%
  select(starts_with("review_scores")) %>%
  rename_with(~ str_remove(.x, "review_scores_")) %>%
  vis_miss()

Estos casos (rating presente, alguna subpuntuación ausente) se imputan con la media de las demás subpuntuaciones de la misma fila (mismo listing, misma escala 0-10). Dentro de ese grupo puede haber un subgrupo residual sin ninguna subpuntuación disponible (la media de fila no tendría con qué calcularse); se comprueba antes de aplicar la imputación:

Code 
score_cols <- c("review_scores_accuracy", "review_scores_cleanliness",
                 "review_scores_checkin", "review_scores_communication",
                 "review_scores_location", "review_scores_value")

listings %>%
  filter(has_reviews) %>%
  rowwise() %>%
  mutate(todas_na = all(is.na(c_across(all_of(score_cols))))) %>%
  ungroup() %>%
  summarise(n_casos = sum(todas_na))
# A tibble: 1 × 1
  n_casos
    <int>
1     243

Para ese subgrupo residual (el n_casos del resultado anterior) se aplica un fallback a la mediana global de cada subpuntuación (calculada solo entre listings con reviews), ya que no hay información dentro de la propia fila para imputar:

Code 
listings <- listings %>%
  rowwise() %>%
  mutate(
    media_fila_scores = mean(c_across(all_of(score_cols)), na.rm = TRUE),
    across(all_of(score_cols), ~ if_else(is.na(.x) & has_reviews, media_fila_scores, .x))
  ) %>%
  ungroup() %>%
  select(-media_fila_scores) %>%
  mutate(across(
    all_of(score_cols),
    ~ if_else(is.nan(.x) | (is.na(.x) & has_reviews),
              median(.x[has_reviews], na.rm = TRUE),
              .x)
  ))

Diagnóstico: hay 91.292 listings sin has_reviews, pero 28 de ellos tienen valores reales en las 6 subpuntuaciones pese a no tener rating — es decir, has_reviews (definida solo a partir de rating) no captura correctamente esos 28 casos, que mantienen su información original intacta porque la condición de imputación (is.na(.x) & has_reviews) nunca los tocó. La cuenta cuadra exactamente: 91.292 − 28 = 91.264, el valor observado. No hay ningún error en la imputación.

Limitación conocida y documentada: existen esos 28 casos donde has_reviews == FALSE (por ausencia de rating) pero sí hay valores reales en las subpuntuaciones — una inconsistencia residual del propio dataset (0,01% de las filas). Dado su volumen despreciable, se decide no aplicar un tratamiento especial y documentarlo como limitación conocida, en vez de redefinir has_reviews.
